# Temporal Self-Consistency (TE) 指标：论文用设定

本文档描述离线 TE 指标的定义、协议与已知局限，供论文 Methods / Limitations 章节取用。
实现：`scripts/te_offline.py`。结果：`/data1/logs/te_curve_success.json`。

---

## 1. 指标定义

对一条轨迹的每个动作轮 `t`，设该轮实际发出的动作 token 串为 `a_t`（长度 `n_t`）：

- **成员（members）**：将对话截断到第 `t-1, t-2, t-3` 轮（`k=3`），在每个截断点让模型
  **预测**第 `t` 轮的动作。`q^F` 为这 `k` 个预测分布的平均。
- **当场概率 `π⁰`**：模型在第 `t` 轮完整上下文下给同一串 `a_t` 的概率。

```
gain_tok = ( log q^F(a_t) - log π⁰(a_t) ) / n_t
```

越接近 0 表示时序自洽性越好（提前的预测与当场的判断越一致）。
逐 token、全词表计算，`η = 0.5`。

### 必须同时报告拆分项

`gain_tok` 是一个**差值**，两条互相独立的路径都会让它上升：

- **路径 A（真实改善）**：`log q^F` 上升 —— 模型确实更能提前预判后续动作。
- **路径 B（伪改善）**：`log π⁰` 下降 —— 模型在当场也认为该动作不可能了。

只报 gain 无法区分二者，而我们的数据里**两种情况都真实出现**
（见 §5 的 te250：gain 与 pf250 相同，但 `log q^F` 比 base 还差，全靠 `log π⁰` 暴跌撑起）。
因此论文中每个 gain 数值都应附 `log q^F` 与 `log π⁰` 两个分量。

## 2. 两种协议：own 与 fixed

| | 轨迹来源 | 用途 |
|---|---|---|
| **own** | 每个 checkpoint 用自己评测产出的轨迹 | 与训练中 `te/gain_tok_all` 同口径 |
| **fixed** | 所有 checkpoint 共用同一批轨迹 | 控制轨迹分布，差异只来自权重 |

### own 不可用于任何结论

模型对**自己生成**的轨迹每 token 概率达 0.97–0.98：

| 模型 | own 的 `log π⁰` | 每 token 概率 |
|---|---|---|
| base | -0.140 | 0.87 |
| grpo150 | -0.029 | **0.97** |
| te250 | -0.020 | **0.98** |

分母被压到 0 附近，`gain ≈ log q^F`，指标退化成"预测自己写过的东西"。

**决定性证据**：base 模型参数不变、仅更换轨迹集，
gain 从 **-5.30（own）变到 -1.78（fixed）**，幅度 +3.53 —— 超过大多数
checkpoint 的训练收益。差值指标的分母项完全主导结论。

论文中 own 只应作为"为何需要 fixed 协议"的反例出现。

## 3. fixed 轨迹集的构造（`FIXED_SUCCESS60`）

从三个实验族的 step 50–250 共 15 个 checkpoint 的 SciWorld 200 题评测产物中筛选：

- GRPO baseline（`plan_forecast=False`）
- plan_forecast K=3（`group_norm=False`）
- TE Arm A（plan_forecast K=3 + TE-KL `λ=0.001`, `te_mix=fullvocab`）

三条约束：

1. **只取 `success=True`**（`done` 且 `reward >= 100`）—— 60/60 全部成功
2. **按任务类型分层** —— 覆盖 20 类（SciWorld 测试集共 26 类）
3. **来源在三族间轮转均衡** —— pf 21 / te 20 / grpo 19 条

第 3 条是必要的：若全部取自某一族，该族就是在自己的输出上被打分，
等于把 own 的主场优势搬进 fixed。每条轨迹的来源族与步数记录在
`runs/sciworld_eval/FIXED_SUCCESS60/_manifest.json`。

最终 **60 条轨迹 / 1428 个靶点**，对全部 16 个模型完全相同。

### 为何不能用 base model 的轨迹

早期版本用 base model（Succ 2.50%）评测轨迹的前 25 条，有两个缺陷：

- **成功 0/25**：21/25 reward <= 0（7 条 = -100 判负），18/25 撞满 30 轮
- **字典序取样**：200 题 item_id 跨度 536~4336，字典序前 25 个全落在 1002~1131
  这一连续区间，只覆盖 **4 种**任务（全部是"测熔点"类）

已改为按 item_id **数值**排序 + 分层抽样。

## 4. 参数

| 项 | 值 |
|---|---|
| `k`（成员数） | 3 |
| `η` | 0.5 |
| `skip_invalid` | True |
| 每模型轨迹数 | 60 |
| 序列长度上限 | 8192 token（实测 0 条被截断，最长 2872） |
| 计算方式 | 离线：评测保存的完整轨迹 + 一次前向，**不重新 rollout** |

被评估的 checkpoint：base(Qwen2.5-7B-Instruct) + 三族 × {50,100,150,200,250} = 16 个。

## 5. 结果（fixed 协议，纯成功轨迹）

base: `gain = -1.775`（`log q^F = -3.143`, `log π⁰ = -1.368`）

| ckpt | gain | **Δ vs base** | Δ log q^F | Δ(-log π⁰) |
|---|---|---|---|---|
| grpo50 | -1.408 | **+0.367** | +0.599 | -0.232 |
| grpo100 | -1.673 | **+0.102** | +0.371 | -0.269 |
| grpo150 | -2.117 | **-0.342** | -0.466 | +0.125 |
| grpo200 | -2.289 | **-0.514** | -0.929 | +0.416 |
| grpo250 | -2.322 | **-0.547** | -1.115 | +0.567 |
| pf50 | -0.479 | **+1.296** | +2.065 | -0.769 |
| pf100 | +0.087 | **+1.862** | +1.870 | -0.008 |
| pf150 | +0.236 | **+2.011** | +1.497 | +0.514 |
| pf200 | +0.342 | **+2.117** | +1.548 | +0.569 |
| pf250 | +0.372 | **+2.147** | +1.495 | +0.652 |
| te50 | -0.466 | **+1.309** | +1.993 | -0.684 |
| te100 | -0.077 | **+1.698** | +1.791 | -0.093 |
| te150 | +0.040 | **+1.815** | +0.792 | **+1.023** |
| te200 | +0.038 | **+1.813** | +1.319 | +0.494 |
| te250 | +0.342 | **+2.117** | **-0.454** | **+2.571** |

### 三条结论

**1. 纯 GRPO 不会自发改善时序自洽，符号会翻。**
+0.367 → -0.547 单调下滑，后三点为负。分解显示 grpo150 起 `log q^F` 本身在下降
（-0.466 → -1.115）：纯 GRPO 训练让模型**更不会**提前预判。

**2. plan_forecast 的改善是真实的，路径 A 主导。**
单调上升 +1.296 → +2.147，`log q^F` 从 -3.143 提升到 -1.5 左右并稳住。
pf100 是最干净的点：`log π⁰` 仅变动 -0.008，Δgain 100% 来自预测能力。

需注意这一结论**近乎同义反复**：plan_forecast 直接以"预测未来 k 步动作"为训练目标，
而 TE 指标量的正是该能力。

**3. TE-KL 辅助损失无额外贡献，且 te250 是路径 B 的教科书案例。**
te250 的 gain(+2.117) 与 pf250 数值相同，但 `log q^F` 为 **-0.454**
（预测能力比 base 还差），全靠 `log π⁰` 暴跌 2.571 撑起。te150 同理（路径 A 仅占 44%）。
即 TE-KL 没有带来预测能力，只是把模型推离了成功轨迹的动作分布，
在差值指标上伪装成"改善"。这与端到端评测的负结果一致。

## 6. Limitations（必须写入论文）

### 6.1 离线量是训练指标的**相关代理**，不是复现

同一批 Arm A checkpoint 对照：

| step | 训练 `te/gain_tok_all` | `members_mean` | 离线 own |
|---|---|---|---|
| 50 | -0.375 | 2.43 | -0.987 |
| 100 | -0.165 | 1.97 | -0.491 |
| 150 | -0.110 | 2.01 | -0.175 |
| 200 | -0.093 | 1.94 | -0.276 |
| 250 | -0.017 | 1.90 | -0.031 |

趋势、符号、单调性一致，但离线值系统性偏负 **1.6–3.0 倍**。原因：

- 训练在 **train split 的 rollout** 上计算，离线在 **test split 的评测轨迹**上计算
- 训练的 `members_mean` 仅 1.9–2.4（未满 `k=3`），离线用满 3 个成员

**措辞应为 "a correlated offline proxy"，不可写 "reproduces"。**
（`te_offline.py` 原文档字符串写的是"复现"，该表述不成立。）

本文报告的结论均为"同一批固定轨迹上、不同 checkpoint 之间的**相对**比较"，
不依赖与训练指标的数值等同，故此局限不影响结论有效性。

### 6.2 `skip_invalid` 的覆盖范围有限

只过滤**解析失败**的动作；**语义无效但格式合法**的动作
（如对不存在的门执行 `open door`）仍保留为靶点。这类动作在失败轨迹中占比很高，
而它们正是 RL 最先学会规避的 —— 这会系统性放大路径 B。
本文采用纯成功轨迹正是为了削弱该效应。

### 6.3 统计效力

单次运行、单一随机种子、n=60 轨迹 / 1428 靶点，**当前无误差棒**。
GRPO 曲线的关键差值仅 +0.367 → -0.547，若无置信区间则"单调下滑并转负"
的论断不够稳健。bootstrap CI（按轨迹重采样）与按来源族拆分的稳健性检查
为待补项。

## 7. 复现

```bash
# 构造 fixed 轨迹集
python3 build_fixed_succ.py          # -> runs/sciworld_eval/FIXED_SUCCESS60

# 计算（16 个 ckpt，own + fixed）
bash /data1/logs/te_curve_success.sh # -> /data1/logs/te_curve_success.json

# 仅 fixed + 逐轨迹明细（用于 CI）
bash /data1/logs/te_curve_ci.sh      # -> /data1/logs/te_curve_ci.json
```

实现要点见 `scripts/te_offline.py`，其中两个已修复的关键 bug：

1. **动作 token 定位**：必须在"第 t 个 assistant 消息"的字符区间内定位，
   不能在全序列搜索 token 串 —— 退化轨迹会把同一动作复读几十次，
   取第一个匹配会落在模型已复读多次之后的位置，条件概率接近 1
   （实测 `π⁰` sum = -0.001），导致 gain 被算成正数（符号错误）。
2. **成员 span 与 rollout 动作的 token 数必须一致**，否则是不可比的两个量
   （训练侧 `assemble_te_tensors_token` 有同样的丢弃逻辑）。
